# Notifications and automation

GiveawayX supports several forms of automated delivery. Configure them conservatively, especially when a workflow can ping roles or send repeated messages.

## Giveaway automation

| Automation | How it works |
| --- | --- |
| Scheduled start | Publishes a saved draft at its selected time. |
| Repeat/recurrence values | Retains repeat count, interval, and dashboard recurrence choices. |
| Sticky event | Re-sends a giveaway after members chat; Tier 2 feature. |
| Winner/host DMs | Server defaults and per-giveaway overrides can send custom direct messages. |
| Winner thread | Creates a public or private winner thread with custom name/message when enabled. |
| Giveaway logs | Records lifecycle and settings events in configured log channels. |

## Platform notifications

The server data model includes notification records for **YouTube**, **Twitch**, and **Kick**. Each record includes a destination channel, platform account identity, custom message, optional mention role, last-seen state, enabled state, delivery counters, and creation time. YouTube notifications distinguish videos, Shorts, and streams.

The dashboard contains protected platform-notification endpoints that can list/create platform records and update/delete a selected record. The current sidebar does not expose a dedicated Notifications page, so check the deployed dashboard before treating this as a staff-facing navigation item.

## Webhook use

Webhook behavior appears in several features:

| Feature | Supported webhook behavior |
| --- | --- |
| Logs | Premium opt-in branding can deliver log records under a server-specific bot name/avatar. |
| Sticky messages | Can send in webhook mode with a custom webhook name and avatar. |
| Payments | Patreon, Polar, and PayPal webhook endpoints process subscription-related events. |

Never publish payment webhook URLs, signing secrets, bot tokens, database URIs, or OAuth credentials in a public documentation repository.
