## /afk

Enable AFK status in the current server, or in shared servers where your account is present when you choose the global scope. You cannot enable it again in the same server while the current status exists; send a message in that server first to clear it. The reason cannot contain links, invites, member mentions, `@everyone`, or `@here`, and is truncated to 200 characters. If no reason is entered, or it is blank after trimming whitespace, `AFK` is used.

**Permission:** Everyone (server only)

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `reason` | string | No | Reason shown when members mention you | Maximum 200 characters; links, mentions, and invites are rejected; defaults to `AFK` |
| `global` | boolean | No | Apply the status across shared servers | Defaults to `false`; saves it in the servers the user belongs to, in addition to the current server |

See [AFK status](/features/afk).

## /avatar

Show a user's avatar and banner, if available, or the server icon and banner when `server: true` is selected. Animated account media is shown as GIF and static media as PNG; a button provides a direct link to each available asset. If the server has neither an icon nor a banner, the command displays a notice saying they are unavailable. A context-menu command named **Avatar** is also available by right-clicking a user.

**Permission:** Everyone

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `user` | user | No | User whose images to show | Defaults to the command user |
| `server` | boolean | No | Show the server icon and banner instead of user assets | Optional; when `true`, server assets take precedence |

## /user

Show a user information card with their name and ID, display names, account badges available to the bot, account creation date, membership and role information if they are a member of the server, received reputation, and saved bio if present. The card shows up to five roles and gives the count of any additional roles. The button to set or edit a bio is visible only to the profile owner; it does not appear when viewing another user. Discord's bot interface does not expose all newer profile badges, so badges are limited to data available through the API.

**Permission:** Everyone

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `user` | user | No | User whose information to show | Defaults to the command user |

## /server

Show a server information card, including its owner and creation date; members, approximate online presence, and bots; channels, roles, emojis, stickers, and soundboard sounds; safety settings; boosts, links, system channels, description, and available media. Server image buttons are direct links and appear when the asset is available.

**Permission:** Everyone

The card includes **View Roles** and **View Emojis** buttons. Each opens a user-specific list with **Previous / Next** navigation when there are multiple pages. Each page shows up to 20 items, and navigation buttons are omitted when there is only one page. Roles are ordered by descending position; the list shows each role's name, position, and ID. The emoji list shows each emoji's name and ID and whether it is animated. List results are private to the user who opened them, and interactions must take place in the same server where the button was created.

## /rank

Show a user's level and progress in text and voice XP, text rank, message count, and voice time. A **Rank** context-menu command is also available by right-clicking a user. **The command is temporarily disabled in the current implementation** while the leveling system is being updated, so the options below do not currently produce a card. If re-enabled, the graphical card requires the `canvas` library; when it is unavailable, the implementation displays a text summary instead of an image. Bots do not have level data.

**Permission:** Everyone

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `user` | user | No | User to look up | Defaults to the command user |
| `theme` | string | No | Card appearance | `dark` or `light`; defaults to `dark`; currently has no effect because of maintenance mode |

## /top

Show separate chat and voice activity leaderboards for the server, ranked by XP for the selected period. Five members are shown per page, with Previous and Next buttons and a page number (disabled). The command shows the invoking user's current rank in the list when the data/filtering requirements are met.

**Permission:** Everyone

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `duration` | string | No | Time period | `day`, `week`, `month`, or `all`; defaults to `all` |
| `role` | role | No | Limit results to members with this role |  |
| `page` | integer | No | Results page number | Starts at 1; defaults to 1; the implementation does not define a published upper limit |

The command does not work if leveling is disabled in the server. Recurring periods use reset days defined in server settings; calculations use the daily/weekly/monthly XP fields. See [Leveling](/features/leveling).

## /setxp

Set a member's XP in the server. Bot accounts are not supported. When text or voice XP is set, the implementation adjusts the total by the difference for the selected type, then recalculates the level from the total. This means total XP remains the source of the level and ranking.

**Permission:** Manage Server (`ManageGuild`), Administrator, or bot owner

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `user` | user | Yes | User whose XP to change | Bots are not accepted |
| `amount` | integer | Yes | New XP amount | Minimum 0; the option defines no maximum |
| `type` | string | No | XP type to set | `total`, `text`, or `voice`; defaults to `total` |

## /setlevel

Set a member's level in the server. The implementation converts the requested level to total XP using the leveling formula. The `preserve_xp` option attempts to preserve the remaining progress within the previous level when moving to the new level. Bot levels cannot be set.

**Permission:** Manage Server (`ManageGuild`), Administrator, or bot owner

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `user` | user | Yes | User whose level to change | Bots are not accepted |
| `level` | integer | Yes | New level | From 0 to 999 inclusive |
| `type` | string | No | XP category to change | `total`, `text`, or `voice`; defaults to `total` |
| `preserve_xp` | boolean | No | Preserve current XP progress within the new level | Defaults to `true` |

## /levelsetup

Open the interactive leveling setup panel. The panel shows the current status, subscription tier and limits, notification channel, XP values, activity tracking, rewards, multipliers, XP-exclusion lists, boost events, leaderboard reset settings, level-up messages, and appearance. Changes are saved when applied. A panel session is tied to a user and server and expires after 20 minutes; run the command again to start a new session. Interactions are ephemeral.

**Permission:** Manage Server (`ManageGuild`), Administrator, or bot owner; server only.

### Panel sections and buttons

- **Enable / Disable:** Turn the system on or off.
- **Channel:** Set the general level-up notification channel and separate text and voice notification channels.
- **XP Config:** Configure XP earning, such as message XP and variation, voice XP per minute, and cooldown. If not configured, the displayed defaults are 15 XP per message, variation of 10, and 10 XP per voice minute with a 60-second cooldown.
- **LvlUp Msg:** Configure text and voice level-up messages, and use an Embed or direct message where supported by the settings.
- **Color:** Set the accent color.
- **Role Rewards:** Add a role reward requiring a text level, voice level, or both. Match mode `all` requires every specified level; `any` requires just one. Rewards and their private/direct message can be edited, and rewards can be deleted individually or all at once. Each entry requires a role and at least one text or voice level, with the level between 1 and 999; the maximum number of rewards depends on the plan.
- **Multipliers:** Assign a role an XP multiplier between 0.1 and 10. Adding a multiplier replaces the previous multiplier setting for that same role.
- **No-XP Setup:** Manage roles, channels, and categories excluded from XP.
- **XP Boost Event:** Start an XP multiplier event with a multiplier, duration, and optional reason. Multiplier and duration limits depend on the plan; duration must be at least one hour.
- **Top Settings:** Configure a fixed or rolling leaderboard, weekly and monthly reset days, and the time zone/rolling-window days according to the available fields.
- **Profile Card:** Configure the profile card background; the background URL must start with `http://` or `https://`.
- **Advanced Settings:** Toggle text and voice activity tracking, ignore muted/deafened members, set the policy for removing reward roles on level-up or reset, award only the highest reward, and hide management roles. Voice tracking, custom backgrounds, and some other messages/features require Premium; unavailable buttons are disabled.
- **Streaks:** Enable streaks and set the percentage reward per day. Validation accepts 0–100% per day and up to 0–1000% overall.
- **Reset Data:** Delete XP data for a specific user or reset XP data for the entire server; resetting the server requires typing `CONFIRM` exactly. Reward roles can also be cleared separately and require the same confirmation.
- **Reaction & Channels:** Configure reaction XP and rewards, channel multipliers, and level-up notifications. The panel displays a default of 5 ± 2 XP per reaction and a 30-second cooldown; channel multipliers and role rewards can also be managed.
- **Premium Status:** Show subscription status and a **Refresh** button, with **Back** to return.

The panel does not grant Premium features unavailable on the plan; related features are shown as locked or their buttons are disabled. See [Leveling](/features/leveling).

## /counting

The counting-game management command has been **redirected to the web dashboard**. It does not open a settings panel in Discord: it sends an ephemeral notice and an **Open Dashboard** link button to the counting page in the server dashboard. The notice mentions a data-compatibility issue in older settings and recommends setting up the game again through the dashboard; the implementation also states that the command will be removed within a month. This is a server-only command and requires Manage Server (`ManageGuild`).

### Counting game behavior in the implementation

The message handler ignores bot messages and processes the game only when it is active, not paused, and in a text channel. Members must pass any configured allowed/blocked role restrictions. It accepts non-negative integers; settings may allow text after the number or a mathematical expression, but mathematical expressions are unavailable on the free plan. Under the effective restrictions up through Tier 2, the same user cannot count twice in a row, and a cooldown may be imposed depending on the plan. On an error, the message may be deleted, the sequence may reset to the beginning, or the game may stop, according to the available game settings; some options are limited by Premium. These are game and engine settings, not interactive controls currently provided by the Discord command.

## /starboard

The current command does not open an in-Discord control panel; it sends an ephemeral notice and an **Open Dashboard** button linking to the Starboard page in the web dashboard. The notice points out a data-compatibility issue with older settings, recommends creating the starboard again through the dashboard, and says the command will be removed within a month. The command is exposed to users with Manage Server (`ManageGuild`). The legacy management interface below remains defined in the code and its interaction handlers, but it is not what currently opens when the command is run.

### Starboard interface sections defined in the code

The legacy interface starts with a main panel showing status (active/disabled/paused), format, channel, log channel, star emoji, minimum threshold, saved stars, rewards, and triggers. Changes to its settings are saved immediately.

- **General:** Enable/Disable and Pause/Resume buttons; toggle self-starring; edit the emoji/threshold/color; select text channels for the starboard and log channels; clear the log channel; and select the exclusive group role whose members can award stars.
- **Filters:** Filter by channels and roles, set minimum Discord account age and server join age (non-negative numbers of days, with zero meaning no requirement), ignore NSFW channels, and require an attachment.
- **Restrictions:** Toggle role and channel restrictions, select their lists, and choose their mode (`allow` or `deny`).
- **Behavior:** Set repost prevention from 0 to 3600 seconds, minimum message age, and maximum age (0 means no limit). Advanced options include rules for handling messages, reactions, and members.
- **Builder / Content / Texts:** Configure the starboard post's layout and text. Defined formats are `embed`, `plain`, and `v2`, but acceptance of `v2` depends on whether the database schema allows it; if the schema rejects it, the implementation keeps the previous format. Builder settings include showing author, description, source, image, and timestamp elements; thumbnail settings; a jump button; and two additional links. The thumbnail and additional-link URLs must use an HTTP(S) prefix.
- **Rewards:** Configure star rewards; **Leaderboard** and **Stats** display leaderboard and statistics sections; **Export / Import** opens the data section.
- **Preview:** Preview only the latest starred message. If there are no starred messages or the source cannot be fetched, an ephemeral notice/error is shown.

The legacy panel's permission check also runs in its handlers: bot owner, Administrator, Manage Server (`ManageGuild`), or a member with one of the contest-manager roles registered in the server. See [Starboard](/features/starboard).

## /sticky

The current command does not open a manager in Discord; it sends an ephemeral notice and an **Open Dashboard** button linking to the Sticky page in the web dashboard. The implementation notes a data-compatibility issue with older settings, recommends creating the sticky message again through the dashboard, and says it will be removed within a month. It requires **Manage Messages** (`ManageMessages`). The legacy management interface below remains defined in the code, but it is not what currently opens when the command is run.

### Sticky interface sections defined in the code

The legacy control panel shows the number of sticky messages against the plan limit and their active/paused/disabled statuses. It displays up to six sticky messages, each with an **Open** button; the rest of the list is available through **Manage All**. Its main buttons are **New Sticky**, **Manage All**, **Statistics**, **Templates**, **Variables**, and **Import** only when the plan allows it. Selecting a new channel opens a form with required content (up to 1900 characters), an optional title (up to 200), and an optional color.

- **Manage All / channel selection:** Select a channel to configure a message. The channel picker supports text, announcement, public and private thread, announcement thread, and forum channels. This path supports one sticky message per channel; selecting a channel that already has one opens its settings instead of creating another.
- **Message panel and edit menus:** Manage the message's status, pause/resume state, content, appearance, timing, triggers, roles, schedule, and channel. Editors cover content, title, color, image, and thumbnail; when using the component builder, text blocks, separators, sections, images, and buttons can be added. Each block has **Edit**, **Move Up**, **Move Down**, **Move to #**, and **Delete** buttons. Position is limited to 1 through the number of blocks, and there can be at most 12 blocks.
- **Templates and variables:** Built-in templates are available for announcement, rules, welcome, information, event, and support. The variable guide covers user, server, and channel fields; date/time and timestamp fields; and random values. Variables are enabled only if the placeholders setting is available on the plan.
- **Plan limits shown in the implementation:** Free supports up to 3 sticky messages, a per-message interval, plain content, and one button. Tier 1 supports up to 10 messages, additional intervals, variables, 3 automatic reactions, scheduling, statistics, copy/auto-delete, and some role settings. Tier 2 supports up to 25 messages, keyword triggers, images/thumbnails, per-user cooldown, pinning, priority, templates, and up to 3 buttons. Some detailed feature limits, such as triggers, copying, and importing, follow the plan table in the code; related items may appear locked or unavailable.

Command access is restricted to `ManageMessages`. These are limits and interfaces of the legacy Discord panel as implemented; they do not guarantee that every option is available on every plan or that the panel currently opens from the command. See [Sticky messages](/features/sticky).

## /translate

Translate text, a linked message, or attachments. When more than one input type is provided, processing order is attachments first, then the message, then text. Languages can be searched through autocomplete by name or language code; the source-language list accepts `auto` for automatic detection. The implementation supports common text/code files, PDFs, and images via OCR.

**Permission:** Everyone

| Option | Type | Required | Description | Notes |
| --- | --- | --- | --- | --- |
| `to` | string | Yes | Target language | Autocomplete; must be a supported language |
| `text` | string | No | Text to translate |  |
| `from` | string | No | Source language | Autocomplete; defaults to `auto` for automatic detection |
| `message` | string | No | Link to the message to translate | The message must be in a server with a channel the bot can access; text and/or attached images may be used |
| `attachment` | attachment | No | First file, image, or PDF |  |
| `attachment2` | attachment | No | Second attachment |  |
| `attachment3` | attachment | No | Third attachment | Maximum of three attachments per request |

Supported text formats include extensions such as `.txt`, `.md`, `.json`, code files, `.csv`, `.srt`, and `.vtt`; supported PDFs and image formats include `.png`, `.jpg`, `.jpeg`, `.gif`, `.bmp`, `.webp`, and `.tiff`. Free file-size limits: text 8 MiB, PDF 20 MiB, image 10 MiB. Premium limits: 50, 60, and 25 MiB, respectively. Text submitted for translation is limited to 300,000 characters; text longer than 1,500 characters is also attached in full as a text file, and processing is split into chunks. See [Translate](/features/translate).
