# Logs, backups, and audit history

Logging is the operational record for GiveawayX. Configure it before delegating event management so staff can reconstruct what changed, who changed it, and when a giveaway state transitioned.

## Giveaway and setting logs

The server data model includes log events for giveaway start, end, edit, delete, reroll, pause, resume, drop, last-person events, fixes, schedules, and setting changes such as colour, emoji, roles, pick actions, DMs, threads, language, and logs themselves.

| Log control | Function |
| --- | --- |
| Enable giveaway logs | Turns giveaway logging on or off. |
| Default and event-specific channels | Uses a standard log channel or directs an event type to its own channel. |
| Event categories | Selects which tracked events deliver a record. |
| Visual settings | Premium server-wide/per-category log colours and executor display controls. |
| Webhook branding | Premium opt-in delivery via a branded webhook rather than a plain bot message. |

The dashboard includes **Log Settings**, **Dashboard Logs**, **Audit Logs**, a giveaway-log endpoint, and dashboard-log export. Dashboard and audit logs are separate navigation items: use event logs for giveaway behavior and audit history for administrative activity.

## Premium backups

The dashboard marks **Backup** as Premium. Its protected backup API supports listing, creating, importing, downloading, cloning, updating, deleting, restoring individual backups, and configuring automatic backups.

> A restore can overwrite active configuration. Before restoring, export or download a current backup, communicate the maintenance window, and confirm the selected server and backup record.

## Safe restore workflow

1. Open the target server and confirm its Discord identity.
2. Create or download a current backup first.
3. Inspect the selected backup’s date and purpose.
4. Restore only when you understand which configuration it will replace.
5. Re-check giveaway defaults, channel IDs, role IDs, webhooks, and logs after restore.
6. Record the action in your internal change log.
