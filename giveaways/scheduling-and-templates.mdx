# Scheduling, repeats, and templates

GiveawayX separates a draft’s **start time** from its **duration**. A scheduled giveaway is published automatically at the selected time, then runs for its configured duration. The dashboard offers quick start-time choices such as one hour, six hours, the next day at 9 AM, and one week, as well as a date-time picker.

## Scheduled and recurring giveaways

| Setting | Effect |
| --- | --- |
| **Schedule for later** | Publishes the event at the selected date and time instead of immediately. |
| **Repeat count** | Creates the configured repeated giveaway behavior. The bot marks repeated events and preserves the repeat interval. |
| **Repeat interval** | Stores the interval used by repeat/restart behavior. |
| **Recurring schedule** | Dashboard draft values support none, daily, weekly, or monthly recurrence. |
| **Reminder** | Draft values include a reminder timing and optional reminder role. |

The bot exposes `/gschedule` for Discord-based scheduling. It accepts the core giveaway settings plus `start_time`, template, requirements, media, repeated-event options, sticky mode, server-tag requirement, and minimum level.

## Templates

Use `/gtemplate` or the dashboard’s giveaway-template endpoints to retain a known-good event configuration. The command supports creating, editing basic settings, editing requirements, editing entry/bonus settings, editing media, deleting, listing, viewing, previewing, duplicating, exporting, and importing templates.

A template can keep a prize, duration, winner count, channel, description, entry method, role requirements, activity requirements, bonus entries, announcement copy, media, and relevant repeat/sticky options. When you load a template into a new draft, review the target channel, date/time, and any rule that may have changed since the template was saved.

## Practical workflow

1. Build and test one event configuration.
2. Save it as a template from the draft panel or with `/gtemplate`.
3. Duplicate the template for future campaigns.
4. Adjust only campaign-specific details such as prize, date, media, or ping roles.
5. Use a scheduled start rather than asking staff to publish manually at an exact time.
