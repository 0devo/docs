# Giveaway Studio

The Giveaway Studio is the dashboard form used to create and edit giveaway drafts. It is organised into **Basics**, **Requirements**, **Rewards**, **Appearance**, **Messages**, **Access**, and **Schedule**. Its draft fields are aligned with the bot’s create and edit data model so that the dashboard preserves the selected configuration when an event is published.

## Basics

| Setting | Behaviour |
| --- | --- |
| Prize and description | Defines the visible event title and optional context. |
| Channel and winners | Chooses the destination and winner count. |
| Duration | Supports minutes, hours, and days. Free servers are capped at 60 days, Tier 1 at 100 days, and Tier 2+ at 300 days. |
| Host | Defaults to the staff member creating the event; the host can be hidden or displayed as a clickable mention. |
| Drop mode | Converts a newly created event into an instant-claim giveaway: the first entrant wins rather than waiting for the timer. |
| Announcement message | Sends optional text immediately before the giveaway message. |

The dashboard source applies winner-count limits of **60** for free, **100** for Tier 1, and **200** for Tier 2+ servers.

## Appearance and preview

Each draft has an in-product preview. Administrators can define a colour, bullet style, custom text lines, entry-button colour and label, participant-count visibility, large image, and thumbnail. Image and thumbnail uploads are limited to 5 MB each in the dashboard and are create-only; the dashboard warns that media cannot be changed after publishing, so recreate the event if its visual media must change.

Use these template variables in compatible message and embed fields:

| Token | Replaced with |
| --- | --- |
| `{prize}` | Prize name |
| `{winners_count}` | Number of winners |
| `{host}` | Host display value |
| `{entry_count}` | Entry count |
| `{relative_time}` | Remaining or scheduled time |
| `{user}` | Relevant Discord user |

## Entry methods

A standard giveaway uses a single Discord button. **Reaction entry** is available as a Tier 2 option and lets participants enter with a chosen reaction emoji. The giveaway can also be configured as sticky, which re-sends it to the bottom of the channel after members chat; this feature requires Tier 2.

## Per-giveaway messages

A draft can override server defaults for winner DMs, host DMs, winner-thread creation, thread visibility, thread name, and thread opening text. These settings are useful when one campaign requires special claim instructions without changing global server defaults.

> Publishing an event persists its full draft configuration, including eligibility rules, rewards, visual overrides, access mode, scheduling values, and thread/DM overrides.
