The `/settings` command opens a private interactive panel that only the user who opened it can see. Choose a section from the navigation menu at the top of the panel. Changes are saved when you select an option or submit a form, and the panel updates automatically; the source does not show a general Save button.

## Accessing the panel

The command requires one of the following: the Discord **Administrator** or **Manage Server** permission, or a role listed in the `giveawayManagerRoles` setting (Giveaway Manager roles). Bot owners are also exempt. Permissions are checked again when interacting with the panel's buttons, menus, and forms, so having opened it earlier is not enough if you are no longer authorized. Without permission, the panel displays an error and does not allow settings to be changed.

## Navigation menu sections

The `Jump to a settings section…` menu takes you to the sections below. An asterisk in an option's name is a marker in the bot UI for a Premium feature; it does not, by itself, prove that every setting in that section is paid. The details below distinguish what the source actually checks.

## Sections in detail

<AccordionGroup>
  <Accordion title="Overview" icon="gauge">
    Shows Premium or free-plan status; the winner, host, and global direct-message toggles; winner-thread creation, type, and auto-close duration; entry-button color and label; entry mode; and a summary of bot customization. This is a status display, not a form for editing values. The default embed color in the schema is `#2563FF`.
  </Accordion>
  <Accordion title="DMs & Templates" icon="envelope">
    Three toggles save `sendDmToWinner` to send the winner a direct message when a giveaway ends, `sendDmToHost` to notify the host, and `dmWinnersGlobally`, which forces direct messages for all giveaways, overriding the `/create` DM option according to the panel text. The two **Edit Messages** buttons open template fields for the winner and host; each accepts up to 1500 characters. Leaving a field blank saves `null` and restores the default. The reset buttons restore each template individually to its default.

    The template variables shown are `{prize}`, `{server}`, `{winners_count}`, `{winners_list}`, and `{timestamp}`. Editing and resetting templates are protected by a Premium check in the handler; no Premium check is shown for the three message toggles.
  </Accordion>
  <Accordion title="Winner Thread" icon="comments">
    **Auto Thread** toggles creation of a winner thread after the giveaway (`createWinnerThread`). **Visibility** switches between public and private (`threadType`). **Auto-close Duration** opens a field for minutes: an integer from 0 to 10080, where 0 means no automatic closing according to the UI. **Claim Tracker** toggles prize-claim tracking, and **Ping Winners** toggles whether winners are mentioned. **Claim Deadline** accepts an integer number of hours from 0 to 720; zero means no deadline.

    **Edit Thread** edits the thread name (up to 100 characters), the first message (up to 1500 characters), and the accent color as a six-digit hexadecimal value, with an optional `#`; invalid colors are rejected. Empty fields clear the customization. The Reset Name / Message / Color buttons clear each value individually. The three customizations and their resets are protected by a Premium check; no Premium check is shown for the creation, type, tracking, notification, deadline, or duration toggles.

    The name/message variables shown are `{prize}`, `{prize_short}`, `{host}`, `{channel}`, `{date}`, and `{winners_list}`. This source does not specify the actual archive-duration limits or Discord's requirements for creating a thread.
  </Accordion>
  <Accordion title="Enter Button" icon="hand-pointer">
    The color buttons save `giveawayButtonColor` by choosing **Primary**, **Secondary**, **Success**, or **Danger**. **Set Button Label** opens a label field of up to 80 characters; leaving it blank restores the default behavior, which displays the participant count. The paid label option is protected by a Premium check, as is resetting it to the default.

    The show/hide participants toggle switches `hideParticipantsButton`. The role menu accepts one role or none; selecting a role saves `participantsViewRoleId` to restrict who can view participants, while clearing the selection allows everyone to view them according to the menu description. No Premium check is shown for these options. **Customize Participants Button** saves a label of up to 80 characters, an emoji of up to 100 characters, and a text color of up to 20 characters. The color must match Primary / Secondary / Success / Danger, case-insensitively; a non-matching value becomes Secondary. This customization and resetting its fields require Premium.
  </Accordion>
  <Accordion title="Appearance" icon="palette">
    **Set Color** sets the accent-bar color on giveaway messages for the entire server; it accepts six hexadecimal digits with an optional `#` and saves the color in uppercase. Invalid colors are rejected. **Reset Color** clears the customization. Both require Premium.

    **Customize Labels** provides a multiline field in `key: value` format and a template box. Accepted keys are `ends`, `host`, `winners`, `participants`, and `bullet`; malformed lines and other keys are not applied. The labels field allows up to 1000 characters and the template up to 1500 characters. Empty values clear the customization for that key. **Reset Labels** clears all five labels and the template. The template variables shown are `{prize}`, `{host}`, `{end_time}`, `{winners_count}`, `{info_rows}`, `{extra}`, `{bullet}`, `{lbl_ends}`, `{lbl_host}`, `{lbl_winners}`, `{description}`, and `{enter_button}`.

    **Edit Messages** edits the winner announcement, entry confirmation, and leave confirmation messages. Each has a 1500-character limit, and leaving it blank restores the default. The Reset Winner / Entry / Leave buttons reset each one individually. The variables shown are `{prize}`, `{winners_list}`, `{winners_count}`, `{host}`, `{server}`, and `{date}`. Color, labels, template, messages, and their resets are all protected by a Premium check.
  </Accordion>
  <Accordion title="Entry Mode" icon="masks-theater">
    **Button Mode** makes buttons the default entry method for new giveaways, while **Reaction Mode** makes reactions the default. The default mode is Button; according to the panel text, changing the mode does not affect existing giveaways. Reaction mode requires Premium. When it is selected, **Set Emoji** can set a Unicode emoji or custom Discord emoji (the field accepts up to 50 characters and cannot be empty), and **Reset Emoji** clears the custom emoji and returns to the default. Setting the emoji is also protected by a Premium check. The source does not explain how the validity of a custom emoji ID is checked.
  </Accordion>
  <Accordion title="Bot Custom" icon="robot">
    **Set Nickname** saves a nickname of up to 32 characters and applies it only in this server; an empty field removes the nickname, and Reset Nickname restores it. A nickname requires Premium, and applying it also requires that the bot be allowed to change its nickname; otherwise, an error message appears.

    **Set Avatar** and **Set Banner** save an image URL and apply it to the bot’s member profile in this server only; it does not edit the global bot account profile. Each field accepts up to 500 characters; leaving it blank attempts to remove the custom image. The source downloads the URL over HTTP(S), accepts an HTTP 200 response, and imposes an 8 MiB limit, a 10-second timeout, and a maximum of five redirects; a download or account-update failure displays an error. **Set Bio** saves a bio of up to 190 characters and applies it to the bot’s profile in this server only; leaving it blank clears the bio for this server. The panel has no separate reset buttons for these fields. The source UI describes the avatar, banner, and bio as Ultra Premium (Tier 2), but the handlers for these fields, like the nickname handler, actually check only `isPremium`; this source alone cannot establish a specific tier requirement.
  </Accordion>
  <Accordion title="Premium Dashboard — Premium status" icon="star">
    Shows the status, the tier name calculated from `premiumTier`, and the expiration date if available. **Refresh Status** rechecks Premium status and updates the display. **Upgrade Now** links to the support server; it is not an in-panel purchase flow. The section displays a feature list and support information; it does not change giveaway settings. The tier names displayed in this section may not match the star classifications used in some parts of the UI; the implementation source here is insufficient to document prices, subscription terms, or how to upgrade.
  </Accordion>
</AccordionGroup>

## Limits of what the source establishes

The storage schemas show some defaults, including: winner and host messages enabled; winner-thread creation disabled; thread type public; claim tracking enabled; winner pings disabled; deadline and auto-close duration set to zero; entry button color Primary; participants button visible; entry mode Button; and color `#2563FF`. These values come from server-model fields and do not document every runtime behavior. The available source also does not establish the content of every default template used elsewhere in the application, the effect of the global direct-message option in every giveaway flow, or how deadlines and claim tracking are implemented, so we do not assume those details here.

## How to use the panel

Run `/settings`, choose a section from the menu, then use its buttons, select menus or forms. Most changes save immediately when you select or submit them—there is no general **Save** button. If a button is disabled or returns a Premium message, that specific action has a plan check; a star in a section title alone does not mean every option in the section is paid.

**Reset Nickname** removes the server-specific nickname (sets it back to the default/no-nickname state). Avatar, banner and bio are also scoped to the bot's membership/profile in this server in the current code, not a global change to the bot account. The archive does not include the web checkout or all dashboard UI, so use the Premium status/website for current plan and purchase details.
