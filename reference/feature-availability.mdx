# Feature availability

The current source contains implemented features, premium gates, and dashboard navigation entries explicitly marked as upcoming. This page prevents staff from promising a feature solely because a route or model exists in the codebase.

## Premium gates verified in source

| Feature | Requirement |
| --- | --- |
| Durations beyond 60 days | Tier 1; beyond 100 days requires Tier 2. |
| Winner counts above 60 | Tier 1; above 100 requires Tier 2; Tier 2+ permits up to 200. |
| Repeated giveaways | Tier 1. |
| Sticky giveaways | Tier 2. |
| Reaction entry | Tier 2. |
| Custom giveaway colours, style, button colour/label | Tier 1 in the dashboard form. |
| Custom prefix | Premium. |
| Dashboard Backup | Premium navigation item. |
| Profile Bot | Premium navigation item. |
| Premium log colours, executor identity, webhook branding | Premium fields in log settings. |

## Dashboard items marked Soon

The sidebar explicitly marks the following items **Soon**: Leveling System, Suggestions, Server Tag, Temporary Channels, Boosts, Colors, and Custom Commands. The repository contains source for some of these systems, notably leveling and temporary voice support. Treat the sidebar state as the user-facing availability signal until your deployed dashboard exposes the section.

## New and internal items

**Commands** and **Audit Logs** carry a **New** badge in the sidebar. `/premium-add` and `/premium-removal` are described as developer-only; exclude them from standard end-user documentation and restrict access even for server administrators.

## Testing before launch

The user interface, plan configuration, payment provider, and Discord permissions can change by deployment. Before advertising a feature, test it on a staging server using the same tier and bot permissions as the production community.
