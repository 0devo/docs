# Permissions and access

GiveawayX uses both Discord permissions and product-level roles. Configure least privilege: give staff the narrowest capability they need, and separate routine giveaway management from destructive configuration or billing actions.

## Declared command permissions

| Permission level | Examples |
| --- | --- |
| **Manage Guild** | Giveaway creation and lifecycle commands, language/settings changes, logging, leveling setup, temporary voice setup, and most Premium self-service commands. |
| **Administrator** | `/gfix`; developer-only Premium add/removal commands use Administrator as a proxy but include additional developer checks. |
| **View Channel** | `/glist` is declared with View Channel. |
| **Send Messages** | `/meme` and `/rep` are declared with Send Messages. |
| **Custom checks** | Utility/moderation commands can apply their own role or Discord-permission checks. |

## Giveaway Manager roles

The server model stores a list of **Giveaway Manager roles**. `/gstart` accepts a configured manager role in addition to bot owner, Administrator, or `Manage Guild` permission. Use this to delegate event work without granting full administrator access.

## Dashboard access

Dashboard server APIs are protected by a guild-access guard. In practical terms, a signed-in Discord user must have the right to manage the selected server before using server-specific settings, events, logs, backups, billing, or profile endpoints.

## Safety checklist

| Action | Recommended control |
| --- | --- |
| Delete messages or giveaways | Restrict to trusted moderators or event managers. |
| Restore backups | Require an owner-level approval and a current export. |
| Change premium billing/transfer | Restrict to the subscription owner or owner-approved staff. |
| Configure role pings and webhooks | Test in a private channel first. |
| Change channel permission tools | Use a reason and review the resulting Discord overwrite. |
| Add bot customisation | Preserve original nickname/avatar/banner values for rollback. |
